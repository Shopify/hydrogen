# Dependencies & tooling traps

Read before/while doing the dependency, script, Vite, and config steps of the migration outline. These are "install/build won't even start correctly" traps.

- **`@shopify/mini-oxygen` must be `^4.2.0`.** 4.2.0 is where the `oxygen()` plugin gained `configurePreviewServer` — below it, `vite preview` serves nothing. `@shopify/cli` must be ≥ `4.4.0`, where `shopify hydrogen deploy` gained the `--assets-dir`/`--worker-dir` flags the deploy script passes. Older majors of either "install fine" and fail at the exact step you use them.
- **MiniOxygen compatibility-date workaround (temporary).** Before its own inference catches up, MiniOxygen can infer a workerd `compatibilityDate` newer than the deployed Oxygen runtime supports, so code passes locally and breaks deployed. Pin it explicitly on the plugin: `oxygen()` returns an array — find the `oxygen:main` plugin in it and call `plugin.api.registerPluginOptions({compatibilityDate: '2026-04-01'})` in `vite.config`. Drop this once the installed MiniOxygen infers a date Oxygen supports.
- **`vite` `ssr.optimizeDeps.include` must pre-bundle React + React Router.** In the workerd/SSR build, add `react`, `react/jsx-runtime`, `react/jsx-dev-runtime`, `react-dom`, `react-dom/server`, `react-router`, `react-router > cookie`, and `react-router > set-cookie-parser` to `ssr.optimizeDeps.include` (alongside whatever the app already lists). Omit these and dev/SSR fails with opaque module-interop errors that never point at the real cause.
- **Gitignore the generated typegen.** `.react-router/` (React Router `typegen` output) and `*-graphql-env.d.ts` (the gql schema environments, generated at the **project root**, not under `app/`) are regenerated on install/typecheck — add both to `.gitignore` so they don't land in the migration commit.
