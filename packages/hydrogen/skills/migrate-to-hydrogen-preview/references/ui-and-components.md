# UI & component traps

Read while migrating the product variant form, product/collection lists, and re-owned root/layout. These render fine but are slow, a UX regression, or inaccessible.

- **Variant pickers must select client-side, not navigate.** A classic-Hydrogen product form often renders each option value as a `<Link>` to the variant's URL. Carried over verbatim, every variant change becomes a full route navigation — the selected state doesn't update until the loader round-trip finishes, so the picker feels laggy. Use the library's activation instead: render same-product option values as a `<button {...register('optionValue', {optionName, value})}>` (or call `selectOption(name, value)`) so the selection updates immediately; the caller still owns the UI props (`type`, `aria-pressed`, `disabled`) off `value.selected`/`value.available`. Reserve `<Link>` navigation only for values whose `handle` differs from the current product (a genuinely different page). Easy to miss because the link version still "works" — it's just slow.
- **Presentational primitives left core, not just `Pagination`.** `<Image>`, `<Money>`, `<MediaFile>` and similar hydrogen-react re-exports are no longer exported from `@shopify/hydrogen`. Re-provide them as thin local components — the `hydrogen-image` and `hydrogen-money` packaged skills give the reference implementations. Typecheck flags the broken import, but it's a pile of small components to restore — do it up front rather than one failing route at a time.
- **List pagination is no longer provided by Hydrogen.** The preview library removes `@shopify/hydrogen`'s `<Pagination>` component and `getPaginationVariables` helper (classic Hydrogen shipped both), which gave "Load more" (accumulate nodes across pages + auto-load on scroll) for free. Hand-rolling discrete Next/Previous cursor links is easy but a **UX regression** that silently changes the page; re-implementing accumulate + `IntersectionObserver` auto-load is the faithful option. Decide deliberately per list route and keep them consistent.
- **Accessibility affordances you now own.** Classic-Hydrogen layouts often shipped a working skip-to-content link and route-change focus handling. After you re-own the root/layout, re-verify them: a skip link that is `sr-only` without a `focus:` reveal is permanently unusable; focus should move to the main landmark on navigation (give it `tabIndex={-1}`); and controls that were icon-only need an accessible name. Easy to carry over broken because it renders fine.
- **Prune classic-era client glue.** Swapping to the library primitives (`useCartForm`/`useCart`, the customer-account client, etc.) orphans the hand-rolled hooks and helpers that wrapped the old fetcher/route patterns. They keep compiling, so grep for now-unused ones and delete them rather than leaving dead code that implies a mechanism no longer in use.
