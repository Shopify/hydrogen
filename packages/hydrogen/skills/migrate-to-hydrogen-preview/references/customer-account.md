# Customer account traps

Read before migrating login/logout, `/account*` routes, or any wrapper around the customer-account client.

- **Don't hand-roll Customer Account OAuth.** Use the library: `createCustomerSession(...)` then `prepareLoginUrl` / `handleOAuthCallback` / `logout`. Hand-built authorize URLs get the path subtly wrong — the classic bug is an extra segment, `…/auth/oauth/authorize` instead of `…/oauth/authorize` — and Shopify returns a 4xx even though the page "loaded". The `client_id` is the raw `PUBLIC_CUSTOMER_ACCOUNT_API_CLIENT_ID` value verbatim (no `shp_` transform); getting the client_id "shape" wrong is a red herring — check the **path** first.
- **Customer login needs an HTTPS origin locally.** The library refuses to build an OAuth URL over `http` (`"OAuth origin must use HTTPS"`) and the session cookie is a `__Host-` cookie that requires `Secure`. So `/account/login` throws over plain `http://localhost` even when correctly wired — that is expected. Use the library's `localHttps()` Vite plugin (from `@shopify/hydrogen/vite`): run `npm run dev:https` and open `https://local.tryhydrogen.dev` (resolves to 127.0.0.1); it auto-provisions mkcert certificates, or run `npx hydrogen certs install` once up front (see the `hydrogen-local-https` packaged skill). Register the HTTPS origin's callback URL with the shop admin. Verify the *constructed* URL (path, `redirect_uri`, `scope`, PKCE params) separately from completing the round-trip.
- **If you wrap the customer-account client, type its `query`/`mutate` params as the document, not `string`.** gql.tada's `gql` from `@shopify/hydrogen/customer-account` returns a branded `CustomerAccountDocument` (a string at runtime). A wrapper that declares `query(q: string, …)` rejects every typed document. Type the param as `AnyCustomerAccountDocument` (exported from `@shopify/hydrogen/customer-account`); the underlying client already accepts it.
