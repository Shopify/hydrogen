# Customer account traps

Read before migrating login/logout, `/account*` routes, or any wrapper around the customer-account client.

- **Register the account routes as a handler group; link to them with plain `<a>`/`<form>`.** `createCustomerAccountServerHandlers(…)` (from `@shopify/hydrogen/customer-account`) returns a handler group — add it next to the cart group in the middleware: `handleShopifyRoutes({…, handlers: [cartHandlers, customerAccountHandlers]})`. The group owns `/account/login`, `/account/logout`, `/account/authorize`, and `/account/refresh` (constants `CUSTOMER_ACCOUNT_*_PATH`), so those requests must reach the server: use plain `<a href>` / `<form>` elements, **not** the router's `<Link>`/`<Form>`, which would client-side-navigate into a 404. Do not write route files for these paths. To keep cart buyer identity in sync with login state, create the cart handlers with the same session **and** hand them to the account group: `createCartServerHandlers({customerSession})` plus `createCustomerAccountServerHandlers({customerSession, cartServerHandlers: cartHandlers})`; with `customerSession` set, `cartHandlers.get(…)` also needs `sessionManager` and `requestContext` in its context (see `references/cart.md`). The 2026-10 template skips the sync (plain `createCartServerHandlers()`), which is a valid first migration step.
- **Don't hand-roll Customer Account OAuth.** Use the library: `createCustomerSession(...)` then `prepareLoginUrl` / `handleOAuthCallback` / `logout`. Hand-built authorize URLs get the path subtly wrong — the classic bug is an extra segment, `…/auth/oauth/authorize` instead of `…/oauth/authorize` — and Shopify returns a 4xx even though the page "loaded". The `client_id` is the raw `PUBLIC_CUSTOMER_ACCOUNT_API_CLIENT_ID` value verbatim (no `shp_` transform); getting the client_id "shape" wrong is a red herring — check the **path** first.
- **Customer login needs an HTTPS origin locally.** The library refuses to build an OAuth URL over `http` (`Customer Account OAuth origin must use HTTPS. Use a public HTTPS tunnel for local Customer Account login.`), so `/account/login` throws over plain `http://localhost` even when correctly wired — that is expected. The library sets no cookie of its own; the session cookie belongs to your `sessionManager`, and the template's `__Host-session` cookie additionally requires `Secure`. Use the library's `localHttps()` Vite plugin (from `@shopify/hydrogen/vite`): run `npm run dev:https` and open `https://local.tryhydrogen.dev:5173` (resolves to 127.0.0.1); it auto-provisions mkcert certificates, or run `npx hydrogen certs install` once up front (see the `hydrogen-local-https` packaged skill). Register the HTTPS origin's callback URL with the shop admin. Verify the *constructed* URL (path, `redirect_uri`, `scope`, PKCE params) separately from completing the round-trip.
- **If you wrap the customer-account client, type its `query`/`mutate` params as the document, not `string`.** gql.tada's `gql` from `@shopify/hydrogen/customer-account` returns a branded `CustomerAccountDocument` (a string at runtime). A wrapper that declares `query(q: string, …)` rejects every typed document. Type the param as `AnyCustomerAccountDocument` (exported from `@shopify/hydrogen/customer-account`); the underlying client already accepts it.
- **Current-build quirks — re-verify against the installed version before working around them.** In `2026.10.0`: (1) the package's `./customer-account` export has no `development` condition while `.` does, so under `vite dev` the core bundle (`dist/development/…`) and the customer-account bundle (`dist/customer-account/…`) are two module instances with different brand `Symbol`s. `createCustomerAccountServerHandlers({cartServerHandlers})` then throws `cartServerHandlers must be created by createCartServerHandlers with the customerSession option.` even when they were. Workaround: under `vite dev`, omit `cartServerHandlers` on the account group and `customerSession` on the cart handlers together (TypeScript rejects one without the other); a production build is unaffected because both entries then import the same `dist/core` module. Before assuming a later build fixed it, check `node_modules/@shopify/hydrogen/package.json` → `exports['./customer-account']` for a `development` key. (2) `shopify hydrogen env pull` may write a legacy `PUBLIC_CUSTOMER_ACCOUNT_API_URL` (`shopify.com/<shopId>` shape) — don't pass it as `customerAccountApiUrl` to `createCustomerSession`; omit the option and let the library derive the URL. (2) is unverified against the current CLI; test the direct wiring first.
