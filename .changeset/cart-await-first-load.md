A cart change made while the store is still loading the cart in the browser now builds on the loaded cart. Before, a shopper who clicked Add to cart before `/api/cart` returned saw only the new line, and the store sent the change before it knew the cart, so a cart with 3 of an item showed 1 until a second cart fetch brought back the rest. The change now shows at once, `loading` and `readyPromise` keep describing the load, and the request waits until the load lands, returns no cart, or fails. When the load lands, the change is shown on top of the loaded cart and then sent. `hydrate()` during the load does the same with the cart you pass it. A discount code applied during the load now keeps the codes the loaded cart already had, so the sent list is the loaded codes plus the new one. A promise `initialData` that has not settled after 30 seconds now counts as a failed load, so changes made in the meantime are sent instead of waiting. A change sent from code with `window.Shopify.actions.updateCart` during the load is already on the network, so it still ends the load and the store refreshes the cart. The `hydrogen-cart-ui` and `hydrogen-setup` skills now read the cart in the React Router cart route's loader instead of the root loader, so the data responses of other routes are no longer private, and the `migrate-to-hydrogen-2026-10` cart reference says the same. While `loading` is `true`, `lines` can now hold the changes made so far, so show those lines with a loading note instead of a skeleton, and disable the controls of lines whose ID starts with `optimistic:`. A change made while an add is creating the cart now waits for that add, so it reaches a cart that exists.
