# Dependencies & tooling traps

Read before/while doing the dependency, script, Vite, and config steps of the migration outline. These are "install/build won't even start correctly" traps.

- **`@shopify/mini-oxygen` must be `^4.2.0`.** 4.2.0 is where the `oxygen()` plugin gained `configurePreviewServer` — below it, `vite preview` serves nothing. `@shopify/cli` must be ≥ `4.4.0`, where `shopify hydrogen deploy` gained the `--assets-dir`/`--worker-dir` flags the deploy script passes. Older majors of either "install fine" and fail at the exact step you use them.
- **`buildDirectory: 'dist'` in `react-router.config.ts` is load-bearing.** React Router's default build directory is `build/`, but the deploy script hard-codes `--assets-dir dist/client --worker-dir dist/server`. Omit the config value and the build "works" while deploy uploads nothing (or stale output). Set it explicitly and keep the flags and the config in step (the `hydrogen-oxygen` packaged skill describes the layouts `shopify hydrogen deploy` accepts).
- **`localHttps()` requires `enabled` — it does not self-detect the script name.** The plugin's options type requires `enabled: boolean`. Compute it in `vite.config`: `const enabled = process.env.npm_lifecycle_event === 'dev:https'`. Calling `localHttps()` bare (expecting it to read `npm_lifecycle_event` itself) fails typecheck or leaves HTTPS permanently off.
- **Use the env-var names from the 2026-10 template (`.env.example` and `app/lib/env.ts`).** Store: `PUBLIC_STORE_DOMAIN`, `PUBLIC_STOREFRONT_ID`, `PRIVATE_STOREFRONT_API_TOKEN`, optional `PUBLIC_STOREFRONT_API_TOKEN` (the public client uses the real store with or without it), optional `PUBLIC_CHECKOUT_DOMAIN`, and `MOCK_SHOP=1` to force the mock.shop demo. Customer accounts: `SHOP_ID` (the numeric shop id), `PUBLIC_CUSTOMER_ACCOUNT_API_CLIENT_ID`, `SESSION_SECRET` (signs the session cookie). A missing or empty `PRIVATE_STOREFRONT_API_TOKEN` must select the **public** client against the real store — never silently fall back to mock.shop, which is only for `MOCK_SHOP=1` or a store with no domain. mock.shop 401s the private-token header, and the client itself rejects an empty token string.
- **`vite` `ssr.optimizeDeps.include` must pre-bundle React + React Router.** In the workerd/SSR build, add `react`, `react/jsx-runtime`, `react/jsx-dev-runtime`, `react-dom`, `react-dom/server`, `react-router`, `react-router > cookie`, and `react-router > set-cookie-parser` to `ssr.optimizeDeps.include` (alongside whatever the app already lists). Omit these and dev/SSR fails with opaque module-interop errors that never point at the real cause.
- **Gitignore the generated typegen.** `.react-router/` (React Router `typegen` output) and `*-graphql-env.d.ts` (the gql schema environments, generated at the **project root**, not under `app/`) are regenerated on install/typecheck — add both to `.gitignore` so they don't land in the migration commit.
