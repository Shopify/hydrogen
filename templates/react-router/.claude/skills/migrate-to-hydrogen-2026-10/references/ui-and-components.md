# UI & component traps

Read while migrating the product variant form, product/collection lists, and re-owned root/layout. These render fine but are slow, a UX regression, or inaccessible.

- **Variant pickers are progressively-enhanced links, not `<button>`s and not plain navigation.** Two ways to get this wrong. Carried over verbatim, a classic form's `<Link>` per option value makes every variant change a full route navigation — laggy, selected state waits on the loader round-trip. But replacing the links with bare `<button>`s breaks the no-JS path and loses the crawlable URLs. The library's pattern (follow the `hydrogen-variant-form` packaged skill): render every same-product option value as a **real `<a href>` GET link**, then spread the product-form store's `register(…)` props on it so JS intercepts the click and `selectOption(name, value)` updates the selection client-side without navigating; the return value of `selectOption` tells you when a genuine navigation (different product `handle`) is still needed. A disabled `<button>` is only for values with `exists: false` (no variant combination at all). The store side is `createProductFormStore`/`createProductFormRegister` + `getSelectedVariant`; React apps get `createProductComponents()`/`useProductForm` from `@shopify/hydrogen/react`.
- **Some presentational primitives left core — but check before shimming.** `<Image>` and `<MediaFile>` component re-exports are no longer exported from `@shopify/hydrogen` — the `hydrogen-image` packaged skill gives the local reference implementation. `<Money>` needs no local shim anymore: core exports `formatMoney()` and the `hydrogen-money` packaged skill builds on it. Helpers such as `flattenConnection` and `getSelectedProductOptions` (and the `MoneyV2` type) are exported from core again — verify against the installed package's exports before writing a local copy. Typecheck flags the broken imports; resolve them up front rather than one failing route at a time.
- **List pagination: use the collection store, do not hand-roll.** Classic `<Pagination>` and `getPaginationVariables` are gone, but the library now ships a collection-browse suite: `createCollectionStore`/`createCollectionReconciler` plus filter/sort helpers (`parseCollectionParams`, `serializeCollectionParams`, `getFilterRemovalUrl`, `getSortByValue`) and React `CollectionProvider`/`useCollection*`. The `hydrogen-collection-browser` packaged skill gives the pattern: a GET-degradable browse form, and "Load more" as a real GET cursor link that JS upgrades to append-in-place. Hand-rolling accumulate + `IntersectionObserver` (or downgrading to bare Next/Previous links) is now a divergence from the library, not the faithful option.
- **Accessibility affordances you now own.** Classic-Hydrogen layouts often shipped a working skip-to-content link and route-change focus handling. After you re-own the root/layout, re-verify them: a skip link that is `sr-only` without a `focus:` reveal is permanently unusable; focus should move to the main landmark on navigation (give it `tabIndex={-1}`); and controls that were icon-only need an accessible name. Easy to carry over broken because it renders fine.
- **Prune classic-era client glue.** Swapping to the library primitives (`useCartForm`/`useCart`, the customer-account client, etc.) orphans the hand-rolled hooks and helpers that wrapped the old fetcher/route patterns. They keep compiling, so grep for now-unused ones and delete them rather than leaving dead code that implies a mechanism no longer in use.
